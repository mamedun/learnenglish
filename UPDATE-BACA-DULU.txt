LANGKAH PAKAI
1. BACKUP dulu (lokal dan server): file SQLite produksi beserta -wal/-shm, folder
   api/uploads, serta .env/config lama.
2. Extract zip ke folder project (pilih overwrite). Boleh juga ke folder kosong baru.
3. Hapus file lama yang sudah diganti (daftar di bawah).
4. Periksa api/config.php sebelum dipakai di produksi:
   - APP_ENCRYPTION_KEY: jika server produksi Anda sebelumnya punya .env dengan
     APP_ENCRYPTION_KEY sendiri, isi dengan nilai LAMA itu agar API key provider yang
     terenkripsi di database produksi tetap terbaca. Kunci berbeda = key itu tidak
     terbaca lagi (semua sesi login juga terputus sekali).
   - ADMIN_PASSWORD hanya dipakai saat akun admin belum ada. Setelah admin berhasil
     login dan mengganti password, hapus/kosongkan nilainya.
   - DATA_DB_PATH tidak diisi di file ini, sehingga defaultnya api/db/data.db. Jika
     database produksi ada di lokasi lain, tambahkan path ABSOLUT-nya.
   - CORS_ALLOWED_ORIGINS: sesuaikan dengan origin frontend Anda bila API beda origin.
5. Lokal: npm ci ; php -S 0.0.0.0:8787 api/router.php ; npm run dev
6. Produksi: upload ISI dist/ (termasuk file tersembunyi .htaccess) ke /learnenglish/
   dan folder api/ ke /learnenglish/api/. Jangan hapus atau timpa api/db dan
   api/uploads di server. Tes: /learnenglish/api/health, lalu hard refresh (Ctrl+F5).
7. Jika health 503: baca "code" dan "diagnostics" di responsnya (lihat README bagian
   Menangani 503). Jika 500: pastikan user PHP dapat membaca api/config.php
   (mis. chmod 640 dengan group web server) dan api/config.example.php ikut ter-upload.
